## New concept introduced: stack vs heap

**Labels were initially swapped** — user called stack "heap" and vice versa. Corrected.

**Stack:**
- Automatic, tied to function lifetime
- Compiler arranges it; cleaned up when function returns
- Fixed size, fast

**Heap:**
- Explicit: requested with `new`, released with `delete`
- Persists until manually freed, regardless of which function created it
- Required when: (1) data must outlive its creator function, (2) size is unknown at compile time

**Memory leak:** heap memory that becomes unreachable but unfreed. In short programs, the OS reclaims it on exit. In long-running processes (pricing servers, data feeds), leaked memory accumulates and eventually crashes the process.

**RAII motivation:** tie heap lifetime to a stack object's destructor. When the stack object goes out of scope, the destructor runs and frees the heap. `std::vector` does this — its destructor calls `delete` on the heap block automatically.

### Vector internals — [FIRST TIME]

User correctly identified:
- The `std::vector` object itself lives on the stack (small control block: pointer + size + capacity)
- The actual data (the doubles) lives on the heap — size unknown at compile time

This is the foundational mental model for W6 (classes + RAII).
