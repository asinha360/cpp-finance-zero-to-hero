## What changed in bs_pricer.cpp

### 1. Helper functions extracted
`compute_d1` and `compute_d2` now exist as standalone functions. Before: d1 was computed inline in `blackScholesCall`, `blackScholesPut`, `delta`, and `vega` — four copies of the same formula. After: one definition, four callers.

`compute_d2` takes d1 as a parameter rather than recomputing it — avoids calling `compute_d1` twice per pricing call.

### 2. Assert placed in compute_d1
`assert(sigma > 0 && T > 0)` lives in `compute_d1`. Reasoning: that's where the division by zero would actually happen. Every function that could crash now crashes through the same guard without any of them needing to know about it. This is the "most foundational level" principle.

Previously the guards were `if (sigma == 0) { return 1; }` — the "plausible yet misleading" anti-pattern (a pricing function returning 1 looks like a valid price).

### 3. Parity test extended to 20 inputs
Table-driven test: four arrays (test_S, test_K, test_r, test_sigma, test_T), one for loop, one assert. 20 varied combinations covering ITM, OTM, ATM, short-dated (T=1) through long-dated (T=20), low vol (0.1) through high vol (0.9). All pass at 1e-10.

## New concepts

**ITM / OTM / ATM** — [FIRST TIME]
- ITM (in the money): for a call, S > K. Intrinsic value exists now.
- OTM (out of the money): S < K. No intrinsic value yet.
- ATM: S ≈ K. Boundary case.
- Practical use here: vary S/K ratio to stress-test N(d1) and N(d2) across their full range.

**Table-driven testing pattern**
Define test data in arrays, iterate with a single loop. Avoids copy-pasting the assert N times. Unit testing with a formal framework (GoogleTest) defers to W15 — same concept, better tooling.

**Guard placement principle reinforced**
Guard belongs at the function that owns the precondition — not at callers. Callers come and go; the function's preconditions are permanent.
