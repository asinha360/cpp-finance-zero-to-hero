## Histogram — built from scratch

**Algorithm understood and implemented:**
1. Bins: `lower = -4.0`, `bin_width = 0.5`, `num_bins = 16`
2. `std::vector<int> counts(num_bins, 0)` — pre-initialized with 16 zeros
3. Counting loop: `bin_index = static_cast<int>((x - lower) / bin_width)`, clamp to [0, 15], increment `counts[bin_index]++`
4. Print loop: index-based (range-for not applicable — need `i` to compute left edge), `setw(5)` for alignment, `counts[i] / 10000` stars

**Errors made and corrected:**
- `const int& x` in range-for (same type error as before — fixed after one prompt)
- `push_back(bin_index)` instead of `counts[bin_index]++` — conceptual: pre-initialized slots must be incremented, not appended to
- `num_stars * "*"` — Python syntax; C++ needs an inner star loop
- `i < num_bins - 1` off-by-one (missed last bin)
- `int left_edge` instead of `double` (labels truncated to integers)

**Output confirmed:** bell-curve shape visible, symmetric, tails near ±4 sparse.

## Key conceptual wins

- **Range-for vs index loop distinction:** range-for requires an existing collection to iterate over. `rand_vector`'s loop repeats N times without iterating a collection — index loop is correct there. Retrieved unaided.
- **σ asymmetry:** downside of a call is floored at 0 (you don't exercise); upside is unbounded. Higher vol lifts both tails but only the good one benefits you. Stated cleanly without prompting. [FIRST TIME]
- **`push_back` vs indexed increment:** `push_back` grows the vector; pre-initialized slots need `counts[i]++`. Conceptual distinction clear after one explanation.
- **`static_cast<int>(floor(...))` pattern:** explicit narrowing conversion; intent is visible to the reader.
