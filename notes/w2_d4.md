## Summary

Code review of `bond_pricer.cpp`. Two blocking issues found and fixed. Both acceptance criteria pass after fixes. Floating-point equality pattern introduced as a concept to carry forward to W4.

## Blocking issues fixed

**1. Missing `n <= 0` guard.**
The original guard may have been placed after some computation, or omitted entirely. Fix: add `if (n <= 0)` check immediately after reading `n`, before any loop or calculation begins. Prevents undefined behavior on zero or negative period counts.

Note: the guard uses `n <= 0` not `n < 0`. This distinction matters: `n = 0` means zero coupon periods, which is unusual and should be rejected, not silently computed as an empty sum returning 0 + face PV.

**2. WHAT comments removed throughout.**
Comments like `// compute coupon PV` or `// add to running total` describe what the code does. The code already does that — the function name and variable names communicate it. These were removed. Only WHY comments (non-obvious constraints, workarounds, invariants) are retained.

## Non-blocking improvements applied

**Loop condition:** `i < n+1` → `i <= n`. Equivalent, but `i <= n` reads as the direct statement of the intended invariant (iterate for each period 1 through n).

**Floating-point literal precision:** `y == -1` tightened to `y == -1.0`. In C++, `y == -1` compares a `double` against an `int` literal. The compiler performs implicit conversion, so the comparison still works — but writing `-1.0` makes the intent explicit: we are comparing a double against a double literal.

## Concept: floating-point equality pattern

Introduced but not applied yet: comparing doubles with `==` is fragile in general because two doubles that should be mathematically equal can differ by a tiny rounding error. The safe pattern is a tolerance check:

```cpp
if (std::abs(y - (-1.0)) < 1e-9) { ... }
```

For the bond pricer, where `y` comes from a user-typed literal, `y == -1.0` is safe. The tolerance band pattern becomes important in W4 (assert tolerances in the BS pricer tests).
