## Concepts covered

**Arithmetic vs log returns.**

Arithmetic return: `(P_t - P_{t-1}) / P_{t-1}` — how much a price changed as a fraction.

Log return: `ln(P_t / P_{t-1}) = ln(P_t) - ln(P_{t-1})` — natural log of the price ratio.

Key property of log returns: they are additive over time. If you sum log returns from t=0 to t=n, the intermediate prices cancel (via the ln product rule):
```
ln(P1/P0) + ln(P2/P1) + ... + ln(Pn/P_{n-1}) = ln(Pn/P0)
```

Use log returns for compounding over time; arithmetic returns for cross-section comparisons (e.g., comparing two assets at one point in time).

**Sample variance with n−1 (Bessel's correction).**

The population variance divides by N. When estimating variance from a sample, the sample mean is itself estimated — not the true mean — so it is slightly biased toward the data. Dividing by n−1 instead of n corrects for this bias. Called Bessel's correction.

Edge case: with n=1, the denominator (n−1) = 0. Variance is undefined, not a crash. Document: return NaN or refuse.

**`std::vector` mechanics:**
- Declaration: `std::vector<double> v;`
- `.push_back(x)` — append element to end
- `.size()` — returns count (type `size_t`, an unsigned integer)
- Range-for: `for (double x : v)` — iterates all elements

**Signed/unsigned comparison warning:**
`std::vector::size()` returns `size_t` (unsigned). Comparing it with an `int` (signed) via `<` triggers a `-Wextra` warning. Fix: cast the signed integer to `size_t` or use `size_t` for the loop counter.

**`const-ref` parameter — first application in code:**
`returns_vector()` was written to take `const std::vector<double>& prices`. First time const-ref appeared in student-written code (previously scaffolded in W2). Pattern: pass containers by const-ref to avoid copies.

**`<numeric>` library:**
- `std::accumulate(begin, end, init)` — sum all elements starting from `init`
- `std::inner_product(b1, e1, b2, init)` — sum of pairwise products; used for computing sum of squared deviations

**`std::accumulate` precision note:**
Adding many floating-point numbers in sequence accumulates rounding errors. For large totals divided by small elements (large ratio), precision can degrade. For the variance calculation in this program, the numbers are similar in magnitude — no significant precision loss. Relevant to note for future large-scale computations.
