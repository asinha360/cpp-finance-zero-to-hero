## Concepts covered

### Memory model

- RAM as numbered byte-sized lockers; address = locker number
- `double` occupies 8 consecutive lockers; address = first locker number
- Off-by-one on address arithmetic (1000 + 8 = 1008, not 1009) — caught and corrected
- `&x` — address-of operator; `double* p` — pointer declaration; `*p` — dereference
- Three roles of `*`: declaration, read-dereference, write-dereference — confusion flagged and resolved
- Two pointers to same variable: `*p = 20.0` visible through `*q` — retrieved correctly unaided
- References (`double& r = x`): alias, no `*` needed, must bind at declaration, cannot rebind
- Pointer vs reference: null allowed in pointer, not reference; pointer rebindable, reference not
- `const&`: passes one address (no copy), compiler-enforced read-only — "read the original directly, promised not to touch it"

**`*` operator — three roles:**

| Context | Meaning |
|---|---|
| `double* p` | Declaration: "p is a pointer to double" |
| `*p` on the right | Dereference: read the value at p's address |
| `*p` on the left | Dereference-write: write to the bytes at p's address |

**Pointer vs reference:**

| | Pointer `T*` | Reference `T&` |
|---|---|---|
| Null allowed | Yes | No |
| Rebindable | Yes | No |
| Syntax to access value | `*p` | `r` directly |
| Typical use | Optional/nullable links, rebinding, arrays | Function parameters, aliases |

**Function parameter patterns:**

| Signature | Copies? | Caller's data safe? | Typical use |
|---|---|---|---|
| `void f(T v)` | Yes — full copy | Yes (own copy) | Need to modify locally |
| `void f(T& v)` | No — address only | No — function can modify | Intentional in-out parameter |
| `void f(const T& v)` | No — address only | Yes — compiler enforced | Read-only, default choice |

### RNG

- `std::rand` deprecated: weak algorithm, global state, no distribution control
- `<random>` separation: **engine** (raw bits, e.g. `mt19937`) vs **distribution** (shape, e.g. `normal_distribution`)
- Seeding: deterministic sequence from a starting number; same seed → same output byte-for-byte
- Why seeding matters: reproducibility, debugging, auditability — reasoned from first principles without knowing the term [FIRST TIME]
