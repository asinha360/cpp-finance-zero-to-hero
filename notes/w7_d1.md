## New concepts landed

### File I/O — the stream model
- `std::ifstream` opens a pipe from disk to program; `std::ofstream` goes the other direction.
- `std::getline(file, line)` pulls one line of text into a `std::string`.
- Loop idiom: `while (std::getline(file, line))` — `getline` returns the stream; stream converts to `bool` (true = last read succeeded, false = EOF or error).

### Stream-as-bool condition
- Initially: "returns `std::string::npos` when no lines left." — incorrect (confused with `find`).
- Corrected: `getline` returns the stream itself; the stream's boolean state (`.good()` / `.fail()`) drives the condition. No index or sentinel involved.

### Tokenization with `find` / `substr`
- `line.find(',')` returns the index of the first comma; returns `std::string::npos` if not found.
- `line.substr(0, pos)` — date field (0 to comma, exclusive).
- `line.substr(pos + 1)` — price field (everything after comma). Correct; noted that passing `line.length()` as second argument also works but is non-idiomatic.
- Index arithmetic correct: comma at position 10 in `"2024-01-02,476.32"`; price starts at 11 (pos+1).

### Malformed-row guard
- `if (pos == std::string::npos)` catches rows with no comma.
- `std::cerr` for error output (separate stream from `stdout`); `continue` to skip the row and keep reading.
- `break` vs `continue` mechanics stated correctly. Use-case reasoning: `continue` right for CSV (one bad row shouldn't discard the rest); `break` only if the whole file is untrustworthy.

### `\n` vs `endl` vs `/n`
- Bug caught: `"/n"` is a literal forward-slash + 'n', not a newline. Compiler doesn't warn — silent wrong output.
- Fix: `"\n"` (backslash-n is the escape sequence for newline).
- `std::endl` = newline + buffer flush; slower; unnecessary for normal output. Prefer `"\n"`.

### `std::stod` introduced (closing)
- "string to double" — converts `std::string` to `double`.
- Returns `double`; throws `std::invalid_argument` on non-numeric input. **[FIRST TIME]** retrieved meaning and return type unaided.
