### `push_back` vs pre-initialized increment

**Prompt:** "You have `std::vector<int> counts(16, 0)`. Why is `push_back(bin_index)` wrong, and what does `counts[bin_index]++` do instead?"

**Answer given:**
1. `push_back(bin_index)` adds a million more elements (bin index values 0–15) to the vector, ending up with 1,000,016 elements. Pre-allocated slots never touched.
2. `counts[bin_index]++` addresses the pre-initialized slot and increments its counter.

**Assessment:** Core mechanism correct on both parts. One precision sharpened: `push_back` appends `bin_index` (a number 0–15), not the raw sample value. The vector ends up with 16 + N elements where the first 16 are still 0.

#### Exercise 2 — Carry-forward retrieval: `push_back` vs pre-initialized increment

- **Identifier:** Carry-forward — `push_back(bin_index)` vs `counts[bin_index]++` (scored 0 at W5 Day 4)
- **Learning objective:** Distinguish vector growth (appending a new element) from vector slot mutation (incrementing a pre-initialized counter). Applied context: a `std::vector<int> counts(num_bins, 0)` histogram where each slot is a counter, not a container for raw sample values.
- **Approach taken:** Prompt given verbatim: "You have `std::vector<int> counts(16, 0)`. Why is `push_back(bin_index)` wrong, and what does `counts[bin_index]++` do instead?"
- **Hints given:** None.
- **Answer given:**
  1. "`push_back(bin_index)` adds a million more elements to the vector itself, instead of maintaining 16 bins as declared. We end up with raw values each acting as its own bin."
  2. "`counts[bin_index]++` acts as a counter instead of pushing raw sample values, allowing count indexing for each of the 16 bins."
- **Assessment:** Core mechanism correct on both parts. One precision sharpened by Claude after the answer: what gets pushed is `bin_index` (a number 0–15), not the raw sample value. After 1M samples the vector would have 1,000,016 elements: original 16 zeros (untouched) followed by 1M integers all in the range 0–15. User accepted the correction without confusion.
- **Result:** 1/2 — correct mechanism, one terminology imprecision (said "raw values" instead of "bin indices"). The distinction is understood; vocabulary is still consolidating.
- **Complexity note:** N/A.
