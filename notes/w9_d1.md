### Ex 2 — OHLC aggregator data structure design

**Objective:** Choose and declare the right STL container for grouping ticks into 1-minute OHLC bars. OHLC = Open, High, Low, Close — the first, max, min, and last price of a time period.

**Solo attempt:** Conceptual reasoning (no code).

**Container choice reasoning:**
- `std::vector` rejected: flat, positional — no natural way to group by time key.
- Student initially reached for O(1) lookup (unordered_map). After coaching question ("does the output order of bars matter?"), correctly identified: output must be ordered by minute → `std::map` wins because it sorts by key automatically; `std::unordered_map` would require an extra O(n log n) sort pass.
- Key type: student proposed `std::chrono::minutes` (correct long-term) and `long long`. Settled on `int` (minutes since midnight, `hour * 60 + minute`) — simpler, exact, no `<chrono>` complexity needed at W9.
- Value type: initially proposed `std::vector<double>` of 4 elements → coached to named struct (fragile indexing argument landed cleanly).

**Big O note:** Student said "log n access in constant time" conflating O(log n) with O(1). Corrected directly: `std::map` = O(log n) per access (red-black tree); `std::unordered_map` = O(1) average (hash table). **This is a known weak spot — re-test early in next session.**

### Ex 3 — `struct OHLCBar`

**Objective:** Write a struct with four named double fields: open, high, low, close.

**Solo attempt:** Yes.

**First attempt (wrong):**
```cpp
class OHLCBar {
    double open;
    double high;
    double low;
    double close;
}
```
Two bugs: (1) `class` → fields private by default → `bar.open = 100.0` won't compile; (2) missing semicolon after `}`.

**Coaching:** "If you write `bar.open = 100.0` elsewhere in your code, does it compile? Think about what `class` gives you by default." Student correctly diagnosed: `class` → private → inaccessible → need `struct`.

**Corrected (correct):**
```cpp
struct OHLCBar {
    double open;
    double high;
    double low;
    double close;
};
```

**[FIRST TIME]** — first use of `struct` in the curriculum. Understood as "a class where members are public by default."

### Ex 4 — Map declaration and per-tick update block

**Objective:** Declare `std::map<int, OHLCBar> bars;` and write the `.find()`-based per-tick update logic.

**Solo attempt:** Yes.

**Map declaration:** `std::map<int, OHLCBar> bars;` — correct on first attempt.

**Access attempt 1 (wrong):**
```cpp
int min_571 = bars[bars.find(571)];
```
Two errors: `.find()` returns an iterator (a pointer-like object to the key-value pair), not an integer key; result type is `OHLCBar` not `int`.

**Coaching (iterator vs direct access):** "`.find()` returns a pointer-like object, not a key. For direct access, what operator do arrays use? What would `bars[571]` give you?" Student understood: `bars[571]` returns the `OHLCBar` at key 571 (creating a default one if absent); map keys are labels (associative), not positions (sequential). **[FIRST TIME]** positional vs associative indexing distinction stated cleanly.

**Default-construction behavior introduced:** `bars[571]` when key absent → creates `OHLCBar{0,0,0,0}` at that key and returns a reference. Contrast: `.find()` checks existence without creating.

**Sentinel values:** default 0.0 is wrong for both high (should start at `std::numeric_limits<double>::lowest()`) and low (should start at `std::numeric_limits<double>::max()`). Student reasoned to this correctly from first principles.

**First-tick approach chosen:** `.find()` approach preferred over sentinel constructor — since `open` must be set to the first tick's price (not a sentinel), distinguishing first tick from subsequent tick is unavoidable. The `.find()` approach makes that logic explicit.

**Per-tick update block — evolution:**

Attempt 1 (multiple errors):
```cpp
int minute = timestamp;
if (bars != bars.find(minute)){
    high = std::max(bars.find(minute));
    low = std::min(bars.find(minute));
}
bars[minute].open = tickPrice;
```
Errors: wrong condition (passing iterator to `!=` on the container); `std::max` needs two arguments; `bars.find()` returns iterator not double; open set on every tick (should be first tick only); missing close.

Attempt 2: Fixed condition to `it == bars.end()`, fixed to `{price,price,price,price}` aggregate init, corrected `std::min` for low. Still missing close.

Attempt 3 (correct):
```cpp
auto it = bars.find(minute);
if (it == bars.end()) {
    bars[minute] = {price, price, price, price};
} else {
    it->second.high  = std::max(it->second.high, price);
    it->second.low   = std::min(it->second.low,  price);
    it->second.close = price;
}
```

Note: student attempted `it->second.close = std::back(it->second.close, price)` — `std::back` is not a comparison function; close = direct overwrite.
