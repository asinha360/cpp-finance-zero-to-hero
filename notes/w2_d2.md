**Guard placement:** Guards for `y == -1.0` and `n <= 0` placed before any computation begins. Correct: the function should refuse before doing work, not after.

**Loop structure:** Loop ran `i = 1` to `n` to sum coupon PVs. Initial attempt used `i < n+1` which is equivalent to `i <= n` — identified in Day 4 code review and cleaned up.

**`n` typed as `int`:** Integer type for the number of periods. Correct: avoids floating-point for a count. The integer division trap does not apply because coupon amounts are `double`.

**WHAT comments removed:** First draft contained comments describing what each line did ("compute coupon PV", "add to sum"). These were removed — the code itself is readable enough. Comments should only encode WHY, not WHAT.

## Concepts landed

**`r` vs `y` distinction in code:** The formula uses `y` (yield) as the discount rate in the denominator. The coupon payment C is given as an input — not computed from r × F in this version. The distinction between coupon rate and yield was reinforced in code by seeing the two as separate inputs.

**`const-ref` for vector parameters (introduced):** When a function receives a `std::vector`, passing by value copies the entire container — expensive. Passing `const std::vector<double>&` passes a reference (no copy) and `const` promises not to modify it. This pattern was introduced here and scaffolded; first application in code came in W3.
